# 书籍概念识别工作流

> 用途：从完整书籍、章节或节选中识别值得长期保存、能够支持理解和跨来源连接的核心概念，并输出概念定义、关系、层级及维护建议。

# 触发条件

仅当 `ingest.md` 将来源判定为完整书籍、书籍章节或书籍节选，并开始识别 concepts 时，使用此工作流。文章、论文、研究笔记和其他非书籍来源不得使用此工作流。

如果无法根据扉页、书目信息、目录或章节结构可靠判定来源是否属于书籍，先询问用户。执行本工作流时只在内存中生成分析结果，将结果返回 `ingest.md` 的确认清单；用户确认前不得写入 wiki 派生页面。

如果输入仅覆盖章节或节选，在分析标题和确认清单中明确标记“部分识别”，不得声称覆盖全书。

# 概念判定标准

一个候选内容只有满足以下至少两项，才应被识别为概念：

1. 作者直接定义、反复解释或明确命名。
2. 它参与多个关键主张或论证。
3. 它能够解释某种现象、机制、关系或方法。
4. 它是全书结构中的重要组成部分。
5. 删除它会明显削弱对作者思想的理解。
6. 它能够脱离单一例子，被应用于其他情境。
7. 它与其他概念形成上位、下位、组成、对比、因果或依赖关系。

优先识别以下类型：

- 原理：解释为什么某件事成立。
- 机制：解释某件事如何发生。
- 方法：说明如何完成某项任务。
- 模型／框架：组织多个概念或步骤。
- 分类：划分不同类型或层次。
- 区分：澄清容易混淆的对象。
- 状态／属性：描述对象的重要特征。
- 评价标准：判断某事是否成立或完成的依据。
- 产出：某种方法预期生成的稳定结果。

下列内容默认不作为独立概念：

- 人名、组织、地点、作品名等实体。
- 仅出现一次且没有解释作用的普通名词。
- 只用于说明观点的单一故事或案例。
- 没有独立含义的章节标题。
- 作者引用但没有采用或发展的他人术语。
- 与其他概念完全同义、没有必要单独维护的表达。
- 过度宽泛的词，如“知识”“问题”“方法”，除非作者赋予了特殊含义。

# 证据约束

1. 只能把输入文本实际支持的内容归于作者。
2. 概念必须是单一、可独立定义的语义单元，含“与、和、及、以及、／”等并列表达的候选不得作为概念页。
3. 不得根据书名、常识、模型记忆或外部资料补写概念。
4. 每个概念必须提供章节、页码、段落或行号定位。
5. 严格区分：
   - 【原文定义】：作者直接给出的定义；
   - 【文本归纳】：根据多处文本归纳出的定义；
   - 【合理推断】：作者没有明确命名，但结构上存在的概念。
6. 不得伪造引文、页码、概念名称或概念关系。
7. 如果只提供部分文本，必须标记为“部分识别”，不得声称覆盖全书。
8. 如果证据不足，保留候选状态，不要强行创建概念。
9. 概念名称应简洁、稳定并体现作者实际用法；不要为了显得专业而创造新术语。

# steps

## step1 提取候选概念

从以下位置寻找候选概念：

- 作者直接定义的术语；
- 章节反复出现的关键词；
- 关键主张中的核心名词；
- 方法步骤所依赖的对象；
- 作者明确建立的分类和区分；
- 论证中的重要原因、机制和评价标准；
- 总结、序言、结论及章节首尾反复强调的内容。

## step2 验证候选概念

对每个候选概念检查：

1. 作者是否明确定义或稳定使用？
2. 是否影响多个主张或章节？
3. 是否具有独立的解释作用？
4. 是否能与其他概念建立明确关系？
5. 是否只是实体、案例、同义词或普通词？
6. 是否值得创建独立概念页？

## step3 规范化概念

1. 确定正式中文名称。
2. 保留作者使用的原始术语或英文名称。
3. 合并同义词、别名和不同译法。
4. 区分容易混淆但实际不同的概念。
5. 若需要生成文件名，使用：
   english-slug(中文概念名).md
6. 英文 slug 使用小写 ASCII 和连字符，不使用空格。

## step4 建立概念关系

关系类型只能从以下列表选择：

- `is-a`：是某个上位概念的一种。
- `part-of`：是某个体系的组成部分。
- `requires`：依赖另一个概念。
- `produces`：产生某种结果。
- `enables`：使另一项活动成为可能。
- `contrasts-with`：与另一个概念形成对比。
- `precedes`：在流程中先于另一个概念。
- `refines`：细化另一个概念。
- `applies-to`：适用于某类对象。
- `related-to`：存在重要关系，但类型暂不明确。

只有文本能够支持时才建立关系；不得为了形成完整图谱而臆造连接。

# 输出格式

## 1. 核心概念

| 概念     | 工作定义   | 类型                                                                           | 识别依据                       | 关键证据与定位 | 置信度       |
| -------- | ---------- | ------------------------------------------------------------------------------ | ------------------------------ | -------------- | ------------ |
| <概念名> | <简洁定义> | <原理、机制、方法、模型／框架、分类、区分、状态／属性、评价标准、产出中的一种> | <原文定义／文本归纳／合理推断> | <证据与定位>   | <高／中／低> |

## 2. 概念关系

| 来源概念 | 关系       | 目标概念 | 关系说明 | 证据与定位   |
| -------- | ---------- | -------- | -------- | ------------ |
| <概念A>  | <关系类型> | <概念B>  | <说明>   | <证据与定位> |

## 3. 概念层级

- <上位概念>
  - <下位概念>
    - <更具体概念>

无法确定层级时，不要强行归类。

## 4. 概念簇

| 概念簇   | 包含概念   | 共同问题                   | 在全书中的作用 |
| -------- | ---------- | -------------------------- | -------------- |
| <概念簇> | <概念列表> | <这些概念共同解决什么问题> | <作用>         |

## 5. 概念维护建议

| 概念   | 建议动作                                     | 目标文件名                    | 理由   |
| ------ | -------------------------------------------- | ----------------------------- | ------ |
| <概念> | <新增／更新／合并／跨书关联／保留候选／忽略> | <english-slug(中文概念名).md> | <理由> |

如果提供了已有概念列表：

- `新增`：没有匹配的已有概念。
- `更新`：与已有概念相同，但本书提供了新增信息。
- `合并`：只是本书内已有概念的同义词或别名，与其归并为同一页面。**仅适用于同一本书内部**；不同书籍之间即使概念相同也不得使用 `合并`。
- `跨书关联`：与其他书籍中已有的概念存在类比、对比、细化或依赖等关系，但定义、论证方式或作者归属不同，不合并为同一页面，只建立关联（见第 6 节）。
- `保留候选`：可能值得维护，但证据暂时不足。
- `忽略`：属于普通词、实体、案例或重复内容。

## 6. 跨书关联候选

仅当 wiki 中已存在其他书籍（`wiki/books/` 下有其他书籍文件夹）时才填写本节；如果这是 wiki 中的第一本书，本节留空并注明“无其他书籍可比较”。

| 本书概念 | 关系类型                                            | 目标概念（书籍） | 关系说明       | 本书证据与定位 | 对方书籍证据与定位 | 置信度       |
| -------- | --------------------------------------------------- | ---------------- | -------------- | -------------- | ------------------ | ------------ |
| <概念名> | <analogous-to／contrasts-with／refines／related-to> | <概念名（书名）> | <说明两者关系> | <定位>         | <定位>             | <高／中／低> |

约束：

- 只能基于两本书文本中都能找到的证据建立关联；不得仅凭概念名称相似或常识臆测关系。
- 关系类型只能从 `analogous-to`（跨作品类比／近似）、`contrasts-with`（对立）、`refines`（细化／深化）、`related-to`（笼统相关，类型暂不明确）中选择；不得使用 `is-a`／`part-of` 等强层级关系跨书连接，除非文本明确支持。
- 本节产出的每一行对应 `跨书关联` 动作，落库时不创建新概念页，只在两本书各自的概念页追加“## 跨书关联”行，并在根 `wiki/concept-table.md` 追加一行。
- 找不到值得记录的关联时，不得为了填满表格而勉强连接。

## 7. 概念页生成约定

对建议动作是 `新增`、`更新` 或 `合并` 的每个概念，在创建或更新概念页前读取 `references/templates/concepts.md`，以该完整模板为基础生成页面。

- 替换模板中的 frontmatter、概念名称、重点概念卡片、工作定义、作者论证、运行机制、关系、来源证据和来源占位符。
- 保留模板要求的 frontmatter、`#` 概念标题、`## 重点概念卡片`、`## 工作定义`、`## 作者论证`、`## 运行机制`、`## 相关概念` 和 `## 来源`；如果第 6 节存在对应的跨书关联候选，还要填写 `## 跨书关联`。
- 类型为 `原理`、`机制`、`方法` 或 `模型／框架` 时，根据来源证据填写“作者论证”和“运行机制”并提供定位；前者覆盖前提、证据、推理过程和结论，后者覆盖输入或触发条件、组成或步骤、因果过程及产出。
- 其他类型在“作者论证”和“运行机制”中填写“不适用”。
- 模板字段缺少证据时填写“未知”“不确定”或“无”，不得根据常识、模型记忆或外部资料补齐。
- 重点概念卡片中的“核心机制”保持为一句话摘要，“运行机制”章节提供展开说明。
- 可以在模板标准结构之后追加概念专属章节，但不得删除或替代模板字段。
- `保留候选` 和 `忽略` 不生成概念页，也不写入概念表；`跨书关联` 不生成新概念页，只更新已有的两个概念页和根概念表。

# 与主 ingest 工作流的衔接

1. 将核心概念、关系、层级、概念簇、维护建议、跨书关联候选、模板字段和质量审计完整并入 `ingest.md` 的确认清单。
2. 用户确认后，仅将建议动作是 `新增`、`更新` 或 `合并` 的概念交给关联更新步骤，写入 `wiki/books/{book-slug}(书名)/concepts/`；`跨书关联` 交给关联更新步骤处理已有概念页的追加，不创建新概念页；`保留候选` 和 `忽略` 不创建概念页或概念表条目。
3. `新增`创建概念页，`更新`补充已有页，`合并`归入本书内已有概念且不创建重复页。只有文本支持的关系才能写入页面。`跨书关联` 在两本书各自的概念页追加 “## 跨书关联” 行，并在根 `wiki/concept-table.md` 的 “Cross-book Concept Links” 小节追加一行；两个概念页始终保持独立，不得合并。
4. 所有落库概念页使用 `references/templates/concepts.md` 的完整模板；`原理`、`机制`、`方法` 和 `模型／框架` 必须基于来源填写“作者论证”与“运行机制”，其他类型在两节填写“不适用”；缺少证据的字段明确标记为“未知”“不确定”或“无”，不得补写。自定义扩展只能追加。
5. 高／中／低置信度表示本次文本识别强度，不直接决定书籍概念表或根概念表的状态字段。
