# 基于产品成熟度的研发项目管理模式

## 重点概念卡片

- **正式名称**：基于产品成熟度的研发项目管理模式
- **原始术语／别名**：敏态管理模式、稳态管理模式
- **类型**：模型／框架
- **工作定义**：根据目标产品的技术成熟性、市场准备度和组织能力匹配度，在资金、过程质量控制和结果容错方面采用差异化策略。
- **核心机制**：先区分探索项目与成熟项目，再分别采用敏态或稳态的投资、执行和评价标准。
- **在全书中的作用**：解释研发项目为什么需要差异化的过程、成果物、风险和经费管理。
- **上位概念**：研发项目管理
- **下位概念**：敏态管理模式、稳态管理模式、探索项目、成熟项目
- **相关概念**：[[rd-project-iteration-rounds(研发项目迭代轮次)]]、[[rd-deliverable-tailoring(研发成果物裁剪)]]、[[milestone-based-rd-incentives(里程碑式研发激励)]]
- **适用条件**：可依据产品概念验证、营销体系、技术成熟度和团队经验判断成熟度的 R&D 项目。
- **局限／边界**：探索与成熟并不机械对应某一研发轮次；成熟项目采用 MVP 时意味着其中仍含探索成分，探索项目直接 Scaling 应高度警惕。
- **来源证据**：第 3 章和第 7 章，原文第 6–7、24–25 页；源文件第 108–135、398–423 行。
- **置信度**：高
- **建议文件名**：`maturity-based-rd-project-management(基于产品成熟度的研发项目管理模式).md`

## 工作定义

原文定义：根据目标产品或服务的成熟度差异，在资金分配、研发过程质量与控制、研发结果容错等方面采用不同策略和标准。（第 3 章，第 118–122 行）

## 作者论证

文本认为探索项目通常面临产品概念未充分验证、营销体系不完善、技术不成熟或团队经验不足等不确定性，因此需要小步投入并允许经验证后的失败；成熟项目依托现有产品、成熟技术和营销体系，更适合以可预测目标和投资收益为基准进行严格管理。由此推导出敏态与稳态两类管理方式。（第 3 章，第 108–122 行；第 7 章，第 400–419 行）

## 运行机制

先依据技术、市场和组织能力判断产品成熟度。探索项目按战略一致性、盈利能力、市场吸引力、创新性和资源能力排序并确定分级预算，以假设验证、学习沉淀和里程碑达成为评价重点；成熟项目估算市场规模、成本、收入和 ROI，用 DCF 与价值评分分配预算，以计划目标、进度和质量为评价重点。两类项目都按评估结果拨付资金，但容错边界不同。（第 7 章，第 398–419 行）

## 差异比较

| 维度 | 探索／敏态 | 成熟／稳态 |
| ---- | ---------- | ---------- |
| 投资思路 | 期权式、分级限额 | 实物投资、产品估值 |
| 核心评价 | 假设验证、学习沉淀、里程碑 | 目标、进度、质量、ROI |
| 结果容错 | 允许经过规范验证后的偏差或失败 | 原则上不允许明显目标偏差 |
| 过程方式 | 鼓励敏捷、小步试验 | 强调计划与可预测性 |
