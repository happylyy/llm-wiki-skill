# 研发项目迭代轮次

## 重点概念卡片

- **正式名称**：研发项目迭代轮次
- **原始术语／别名**：MVP、MMF、Scaling
- **类型**：分类
- **工作定义**：从产品创新与生命周期视角，对不同阶段的研发产品和目标进行的轮次划分。
- **核心机制**：用 MVP、MMF、Scaling 将验证、市场化和规模化目标分开管理。
- **在全书中的作用**：决定各项目的研发目标、质量门禁、投资特点和成果物要求。
- **上位概念**：[[product-lifecycle-model(产品生命周期模型)]]
- **下位概念**：最小可行产品、最小可市场化特性、规模化
- **相关概念**：[[maturity-based-rd-project-management(基于产品成熟度的研发项目管理模式)]]、[[feature-validation(特性验证)]]、[[rd-deliverable-tailoring(研发成果物裁剪)]]
- **适用条件**：产品类研发项目；软硬一体项目可将行业里程碑映射到三类轮次。
- **局限／边界**：轮次不等于产品成熟度；同一成熟度可能适用不同轮次，需结合风险判断。
- **来源证据**：第 3、5.2、7、9.1 章，原文第 7、11–12、24–34 页；源文件第 124–135、185–208、408–423、437–506 行。
- **置信度**：高
- **建议文件名**：`rd-project-iteration-rounds(研发项目迭代轮次).md`

## 轮次比较

| 轮次 | 主要目标 | 风险与投资特点 | 典型质量关注点 |
| ---- | -------- | -------------- | ---------------- |
| MVP | 验证市场与技术可行性 | 风险高，控制早期投入 | 核心功能／产品特性完成度 |
| MMF | 形成可销售的完整功能并建立工程能力 | 风险降低，避免过度投资 | 产品特性、解决方案构块、关键非功能特性 |
| Scaling | 标准化、优化并规模化推广 | 确定性较高，需要更大资金 | 架构一致性、系统测试、代码质量、性能与安全 |
