# 技术债

## 重点概念卡片

- **正式名称**：技术债
- **原始术语／别名**：内部质量
- **类型**：状态／属性
- **工作定义**：软件模型与架构所代表的「内部质量」；当其劣化到一定程度，维护难度和成本以指数级方式增长。
- **核心机制**：模型与架构的好坏难以直接观察度量，属「内部质量」；内部质量劣化 → 维护成本指数级增长 → 即「技术债」。
- **在全书中的作用**：软件产品研发管理的三个关键点之一（「管好技术债或内部质量」）。
- **上位概念**：无
- **下位概念**：无
- **相关概念**：价值主张、产品特性（同属三个关键点）、产品生命周期模型（内部质量在打磨完善阶段须保证）
- **适用条件**：适用于软件产品的模型与架构质量评估。
- **局限／边界**：原文未给出技术债的量化度量方法。
- **来源证据**：§5.1「软件的模型与架构决定了软件适应变化的能力，但软件的模型与架构的好坏不容易被直接观察和度量，因而被称为“内部质量”。当软件“内部质量”劣化到一定程度，其维护难度和成本就会以“指数级”方式增长。因此，也可以认为模型和架构所代表的“内部质量”就是软件的“技术债”。」
- **置信度**：高
- **建议文件名**：`technical-debt(技术债).md`
