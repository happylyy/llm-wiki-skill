# 产品生命周期模型

## 重点概念卡片

- **正式名称**：产品生命周期模型
- **原始术语／别名**：无
- **类型**：模型／框架
- **工作定义**：描述软件产品从概念、研发验证、市场验证、打磨完善、规模化投放到终止，并通过新大版本重复演进的阶段模型。
- **核心机制**：用阶段、研发轮次和对应项目类型逐步验证价值、完善质量并控制投资风险。
- **在全书中的作用**：在本文中充当研发投资、项目过程和资产管理设计的共同参照系。
- **上位概念**：软件产品研发生产管理体系
- **下位概念**：可行性验证、市场化验证、打磨完善、放量投产
- **相关概念**：[[rd-project-iteration-rounds(研发项目迭代轮次)]]、[[rd-management-three-domain-model(研发管理三域模型)]]、[[maturity-based-rd-project-management(基于产品成熟度的研发项目管理模式)]]
- **适用条件**：软件产品及允许映射到 MVP、MMF、Scaling 轮次的软硬一体产品。
- **局限／边界**：版本语义的具体规定不在本办法中；行业项目可以按自身里程碑映射轮次。
- **来源证据**：第 5.2 节，原文第 11–12 页；源文件第 185–208 行。
- **置信度**：高
- **建议文件名**：`product-lifecycle-model(产品生命周期模型).md`

## 工作定义

原文定义：产品生命周期模型决定产品“从概念到终止”的全部演进阶段和轮次，各阶段的目标、产物、投入、风险和过程管控要求不同。（第 5.2 节，第 185–190 行）

## 作者论证

文本先提出客户价值、技术债和不确定性风险三个管理关键点，再指出一次性大投入难以客观验证价值和控制风险，因此采用分阶段、分轮次的生命周期模型：先验证商业和技术可行性，再形成最小可市场化特性，随后完善内外部质量，最后规模化交付价值。（第 5.1–5.2 节，第 177–204 行）

## 运行机制

输入是概念产品或一次重大特性变化。研发项目先形成 MVP；天使客户项目将其推进到 MMF；少量合作伙伴项目完成打磨并达到 Scaling；大量市场客户项目负责放量收益。产品还可以通过 V2.0.0、V3.0.0 等新一轮重大版本重新进入验证与演进循环。产出包括经逐步验证的产品、可控的投资节奏和与阶段匹配的管理要求。（第 5.2 节及原文第 10 页图示，第 194–208 行）

## 阶段与项目类型

| 阶段 | 目标产物 | 主要项目类型 | 管理含义 |
| ---- | -------- | ------------ | -------- |
| 可行性验证 | MVP | 研发项目 | 以较小代价验证商业与技术可行性 |
| 市场化验证 | MMF | 天使客户项目 | 与深度参与客户形成可上市的最小功能集 |
| 打磨完善 | Scaling | 合作伙伴项目 | 提升外部质量、内部质量和规模化能力 |
| 放量投产 | 收益与市场规模 | 市场客户项目 | 按期、按预算交付产品价值 |
