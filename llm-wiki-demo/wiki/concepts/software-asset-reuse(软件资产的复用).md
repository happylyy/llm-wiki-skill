# 软件资产的复用

## 重点概念卡片

- **正式名称**：软件资产的复用
- **原始术语／别名**：软件的复用
- **类型**：方法
- **工作定义**：以软件使用者可操作的接口评估软件制品资产的复用性：有人机交互接口时看 UI，有应用程序接口时看 API；通过修改源代码复用不称为软件复用。
- **核心机制**：以软件使用者可操作的接口评估软件制品资产的复用性：有人机交互接口时看 UI，有应用程序接口时看 API；通过修改源代码复用不称为软件复用。
- **在全书中的作用**：规定软件资产是否构成复用的判定方法和边界。
- **上位概念**：软件资产
- **下位概念**：无
- **相关概念**：软件资产、构块、公共构块（CBB）、软件资产全生命周期管理
- **适用条件**：用于原文所述的软件架构设计、治理或数字化生产体系语境。
- **局限／边界**：接口方式使用打包好的组件库源代码可以构成组件复用；直接修改源代码的复用方式不构成这里的软件复用。
- **来源证据**：《软件架构 核心技术语定义》§3.1，行 255–257；以软件使用者可操作的接口评估软件制品资产的复用性：有人机交互接口时看 UI，有应用程序接口时看 API；通过修改源代码复用不称为软件复用。
- **置信度**：高
- **建议文件名**：`software-asset-reuse(软件资产的复用).md`

## 工作定义

## 运行机制

输入是待评估的软件制品及其使用接口；先判断是否存在 UI 或 API，再依据相应接口能否被使用者操作来评价复用性。Go Package、Rust Crate 等即使以源代码交付，也须通过打包组件库的接口使用；直接修改源代码被排除在外（§3.1，行 255–257）。
